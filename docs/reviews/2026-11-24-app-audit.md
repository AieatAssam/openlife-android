## Findings (severity order)

### A-01 — High, confirmed — The lock never engages during a Photo Picker trip, for as long as the trip lasts

- **Where:**
  - `app/src/main/java/org/openlife/app/lock/AppLockState.kt:60`: `onBackground()` returns early while `externalActivity` is set.
  - `MainActivity.kt:105`: `beginExternalActivity()` is called before the picker launches.
  - `MainActivity.kt:100`: `endExternalActivity()` is called only when the result arrives.
- **Problem:** The exemption has no time limit and records no `backgroundedAt`.
- **Scenario:**
  1. Lock is on, set to "Immediately". The user opens the picker, presses Home and leaves the phone.
  2. Hours later someone opens OpenLife from Recents (the picker is still on top) and presses Back.
  3. The result is null, so `endExternalActivity()` runs, and the library is shown unlocked.
- **Docs and tests:** `THREAT_MODEL.md:132` mentions the exemption but not that it is unbounded. `AppLockStateTest.kt:66` writes it down as intended behaviour.
- **Fix:** Record `backgroundedAt` during external trips too. On return, lock if the time away is at least `max(timeout, EXTERNAL_GRACE ≈ 60 s)`. Add a state test for "external trip plus a long absence".

### A-02 — High, confirmed — Extracted text can leave through the clipboard and the keyboard

- **Where:** `app/src/main/java/org/openlife/app/ui/ViewerScreen.kt:92-95` (pre-fills `correctionText = span.text`) and `:209` (`OutlinedTextField`).
- **Problem:**
  - Compose's default text toolbar offers Copy and Cut on OCR-extracted content.
  - The keyboard receives the content and may learn it or offer it as a suggestion.
  - This contradicts design §3 ("No content in … clipboard") and the comment at `OcrPanel.kt:92` ("no selection, links or clipboard").
- **Why tests miss it:** `SourceEgressBoundaryTest` only greps for `ClipboardManager` and `WebView`.
- **Scenario:** The user opens Correct on a span from a medical letter, long-presses and picks Copy. The text is now on the system clipboard, where other apps and clipboard sync can read it.
- **Fix:**
  - Wrap the field in `CompositionLocalProvider(LocalTextToolbar provides <toolbar without copy/cut>)`.
  - Set `KeyboardOptions(autoCorrectEnabled = false)`, and add no-personalised-learning IME options where the API allows.
  - Extend the boundary test to flag every `TextField` or `OutlinedTextField` without that wrapper.
  - The reset-word field holds no content and is exempt.

### A-03 — Medium, confirmed — Tapping Save and then Home leaves the outcome unknown

- **Where:**
  - `app/src/main/AndroidManifest.xml:55`: `noHistory="true"` finishes the activity when it is stopped.
  - `IntakeViewModel.kt:406`: the save runs in `viewModelScope`.
  - `IntakeViewModel.kt:480-491`: `onCleared` treats `Saving` as undecided and calls `cancelAbandonedImport`.
- **Problem:** `ImportRepository.saveImport` can be cancelled (`SourceDao.update` is a suspend function), including between the file rename and the row update.
- **Scenario:** The user taps Save, then Home immediately. Their last sight was "Saving". Depending on timing, the item is either saved or cancelled.
- **Fix:** Run the save on `importHousekeeping.appScope`, or wrap it in `NonCancellable`. Count `Saving` as decided in `onCleared`.

### A-04 — Medium, confirmed — The look is off-brief: colour roles, button shape and fonts

- **Where and what:**
  - `ui/theme/OpenLifeColors.kt:56-108` never sets `surfaceContainer{Lowest,Low,,High,Highest}`, `surfaceBright`, `surfaceDim` or `inverse*`. Material3 (BOM 2026.08.00) falls back to its baseline lavender greys for these. They are used by `AlertDialog` (`surfaceContainerHigh`: the delete, reset and correction dialogs), `DropdownMenu` (`surfaceContainer`) and the unchecked `Switch` track. The result is a Material You look on every dialog.
  - **Button shape:** M3's default `Button` and `OutlinedButton` shape is full radius and is not driven by `Shapes`. Nothing overrides it, so every button is a pill; brief §6 requires 8 dp.
  - **Button font:** `ui/theme/Type.kt:52` sets `labelLarge` (all button text) to `FontFamily.SansSerif`, which renders as Roboto, not Plex Sans.
  - **Unset styles:** `titleMedium` and `titleSmall` are not set, so the section titles at `OcrPanel.kt:42`, `ViewerScreen.kt:241` and `AppLockSettings.kt:62,75` are Roboto.
  - **Fraunces misuse:** `headlineSmall` is Fraunces, so `AlertDialog` titles use Fraunces; the brief forbids it in dialogs. `headlineLarge` is Fraunces SemiBold, where the brief says 600 Plex Sans for headlines and Fraunces 500 with WONK for display. Only the Normal weight of the variable font is registered, so SemiBold is synthesised.
  - **Delete icons:** the list and viewer Delete icons are not in the error colour.
  - **Extracted text size:** OCR span text uses `labelMedium` (14 sp), below the brief's 16 sp body minimum.
- **Why tests miss it:** the goldens include no dialog.
- **Fix:** Set every M3 colour role from the palette. Wrap the button components with an 8 dp shape, or set the shape at each call site. Fix the typography roles. Add a dialog golden.

### A-05 — Medium, confirmed (structural) — The viewer can only open a source that is in the loaded list; the navigation host will not scale

- **Where:**
  - `navigation/OpenLifeNavHost.kt:66-69` (`SourceScreens.find`) and `:197-211`: `ViewerDestination` resolves the source from the list, and shows the list instead while the list is loading.
  - `OpenLifeNavHost.kt:109-128`: the host takes 17 parameters.
  - `OpenLifeNavHost.kt:166-173`: at expanded width the Viewer route pops itself and sets `selectedId`, which is a redirect hack.
  - `MainActivity.kt:47-52`: every ViewModel is scoped to the activity.
- **Scenario:** An event detail screen, a search hit or an evidence link that opens a source not in the loaded list cannot open it. That includes a future paged or filtered list. Each new screen adds more lambdas to this single host.
- **Fix:** See AS-1 to AS-3.

### A-06 — Medium, suspected — Background scrub may not free decoded bitmaps while the app is hidden

- **Where:**
  - `MainActivity.kt:68-76`: `onStop` bumps the epoch, and navigation to the list happens in a `LaunchedEffect` at `:176`.
  - `IntakeViewModel.kt:448-453`: Preview is swapped for Preparing.
  - The bitmaps are owned by `produceState`/`DisposableEffect` at `ViewerImage.kt:58-86` and `IntakeScreen.kt:142-154`.
- **Problem:** Compose pauses its frame clock once the activity is stopped. Recomposition, and with it `onDispose` → `recycle()`, then probably runs only after `ON_START`. The decoded image would stay in memory for the whole background period.
- **Why tests miss it:** `MultiWindowScrubTest.kt:82-88` checks only the scrub counter while hidden, and checks that the image is gone only after resuming.
- **Fix:** Hold decoded bitmaps in a holder that is cleared synchronously from `onStop`, the same way as the thumbnail cache, rather than relying on recomposition.

### A-07 — Medium, suspected — A dropped picker result leaves the lock disabled until the process dies

- **Where:** `MainActivity.kt:97-112`. The launcher is registered inside `UnlockedContent`, and only its callback calls `endExternalActivity()`.
- **Problem:** If the result is never delivered to a live callback (recreation edge cases, or the launcher not being composed), `externalActivity` stays true. `onBackground()` then never locks, and `onUnlocked()`, the only other place that clears the flag, never runs.
- **Fix:** Make A-01's time bound the backstop. Also clear the flag in `MainActivity.onStart` once the activity is resumed with no pending picker request.

### A-08 — Medium, confirmed — Accessibility defects

- **"Section divider" noise:** `ui/brand/BrandComponents.kt:150`. `PerforationDivider` gives every list row a spoken "Section divider". It should be decorative, with no semantics.
- **Buttons without context:** `ui/OcrPanel.kt:123-128`. Every OCR row has "Show region" and "Correct" buttons with no mention of the span they act on, so TalkBack users hear repeated, undifferentiated actions.
- **Evidence overlay not focusable:** `ui/ViewerImage.kt:181-201`. The overlay is a bare `Canvas` and not a focusable node describing the span, contrary to brief §8.
- **Low-contrast borders:** `outline = Rule` (`OpenLifeColors.kt:79`) puts `#D9D1C0` on `#F6F1E7`, about 1.4:1. Text-field and outlined-button borders need 3:1 (WCAG 1.4.11). The brief's mapping conflicts with its own AA rule.
- **Suspected:** `StampBadge` (`BrandComponents.kt:72-90`) sets `contentDescription` on the box and also has a child `Text`, so the label may be announced twice. Use `clearAndSetSemantics`.

### A-09 — Medium, confirmed — Weak and likely flaky tests

- **Unit tests that only grep source text (not evidence):**
  - `app/src/test/.../ui/SecureWindowTest.kt`: its assertion message talks about predictive back.
  - `LargeFontLayoutTest.kt`: passes if a file merely contains `verticalScroll`, `safeDrawingPadding()` or `contentWindowInsets`.
  - `RtlLayoutTest.kt`: checks that another test contains a string.
  - `NavigationBackTest.kt` (unit).
  - `EdgeToEdgeInsetsTest.kt`.
- **Blind spots in `NoHardcodedUiStringsTest`:** it misses interpolated user-visible strings (A-17).
- **Policy baked in as a test:** `AppLockStateTest.kt:66` writes down the unbounded exemption from A-01 as intended.
- **Sleeps:** about 10 `Thread.sleep` polls in the instrumented tests, for example `IntakeAndListFlowTest.kt:79` (1 s per read), `:326`, `:396`, `:557`, `:619`, and `IntakeActivityTest.kt:213`. They will be slow and flaky on shared hosts.
- **Fix:** Replace the grep tests with Compose semantics tests, swap the sleeps for state-based awaits, and fix `AppLockStateTest` once A-01 is fixed.

### A-10 — Low, suspected — Deleting from the viewer may pop twice and blank the NavHost

- **Where:** `OpenLifeNavHost.kt:207` (`LaunchedEffect` → `popBackStack()` when `source == null`) together with `:209`/`:94` (`onClose` → `popBackStack()` after `SourceListViewModel.delete` completes).
- **Problem:** If the Room flow emits before the delete callback runs, both pops happen. The second removes the List start destination and leaves an empty screen.
- **Fix:** Pop only if the current entry is still the Viewer, or use `popBackStack(Routes.List, inclusive = false)`.

### A-11 — Low, suspected — Rotation cancels Verify all and closes the reset dialogs

- **Where:** `settings/ResetVaultFlow.kt:70-92` and `:132-192`. Work runs in `rememberCoroutineScope`, and the stage is held in `remember`.
- **Problem:** The activity has no `configChanges`, so rotation cancels a verify pass and drops the reset confirmation stage.
- **Fix:** Use a settings ViewModel.

### A-12 — Low, suspected — On API 29, unlocking with the device credential may lose a pending share

- **Where:** `AndroidManifest.xml:55` (`noHistory`) together with `BiometricPromptAuthenticator.kt:22-26`, which uses `BIOMETRIC_WEAK or DEVICE_CREDENTIAL` on API 29.
- **Problem:** If the framework's credential fallback starts a separate, non-translucent activity, `IntakeActivity` is stopped and finished in the middle of the unlock.
- **Fix:** Verify on CI's API 29 leg. If confirmed, drop `noHistory` and finish explicitly.

### A-13 — Low, suspected — OCR cleanup stops working after a vault reset

- **Where:** `ui/OcrViewModel.kt:44-55`. `forgetDeletedSources` subscribes once to the database flow that existed before the reset. After a reset, or after an initially unavailable vault becomes ready, it never subscribes again.
- **Fix:** Subscribe again whenever vault access changes.

### A-14 — Low, confirmed — The exported launcher accepts an open-source extra from any caller

- **Where:** `MainActivity.kt:57-61,90,247-250`. Any app can start `MainActivity` explicitly with `EXTRA_OPEN_SOURCE_ID`.
- **Impact:** Limited for now: the lock gates it and UUIDs are hard to guess. But it is the wrong pattern for future notification taps (design §3).
- **Fix:** Require a per-process nonce, as `PickerNonce` does, or route through a non-exported trampoline (AS-5).

### A-15 — Low, confirmed — The read-grant check proves nothing

- **Where:** `intake/IntakeIntentValidator.kt:32-39`. `FLAG_GRANT_READ_URI_PERMISSION` is set by the caller.
- **Problem:** The comment claims the check proves the caller received a grant; it does not. The real defence is that OpenLife holds no media or storage permissions.
- **Fix:** Correct the comment and the threat model so the check is not counted as a control.

### A-16 — Low, suspected — The own-authority check can be bypassed

- **Where:** `intake/IntakeIntentValidator.kt:72-80`. `java.net.URI.authority` includes userinfo and port, so `content://x@org.openlife.y/…` slips past the prefix check.
- **Impact:** None today, since no provider is exported.
- **Fix:** Compare `parsed.host`.

### A-17 — Low, confirmed — Hardcoded or unlocalised strings

- **Raw enum names in About:** `OpenLifeApp.kt:284`, `VaultFailureDiagnostics.summary` builds `"$cause: $count"`.
- **Unlocalised join:** `settings/ResetVaultFlow.kt:104` uses `joinToString(", ")`.
- **Enum compared by name:** `ui/ViewerScreen.kt:246`, `intakeKind.name == "SHARE"`.
- **Test seams in shipped classes:** `IntakeActivity.describeForTest` (English literals), plus public `AppLockController.setForTest` and `resetForTest`, which can inject an authenticator into the shipping lock.

### A-18 — Low, confirmed — Comment overstates how fast a zero timeout locks

- **Where:** `lock/AppLockState.kt:20-22` says a zero timeout locks "at the background transition itself". `ProcessLifecycleOwner` reports stop about 700 ms after the last activity stops.
- **Impact:** Small, because activities scrub on their own `onStop` and FLAG_SECURE covers Recents. The claim should be accurate.

## Structural recommendations (before more screens)

- **AS-1 — Per-destination ViewModels.** Create ViewModels with `viewModel()` inside each `composable<>`, scoped to the back-stack entry and built from an app container on `OpenLifeApp`. Route arguments come in through `SavedStateHandle`. Remove the 17-lambda `OpenLifeNavHost` and the activity-scoped `OcrViewModel`.
- **AS-2 — Load sources by ID.** The viewer and every future detail screen (event detail, facts panel, search result) load their source from the repository by ID, not from the list's state.
- **AS-3 — Make list-detail a real destination.** Use one list-detail destination whose selection lives in the route, replacing the self-popping Viewer redirect.
- **AS-4 — Scrub content without resetting navigation.** On stop, clear decoded content synchronously (see A-06) but keep the back stack, which holds only UUIDs. Otherwise event proposal and confirmation forms lose their input every time the user switches apps.
- **AS-5 — One non-exported entry for internal deep links.** Route "open existing" and future reminder taps through a single non-exported, nonce-checked entry point, never through extras on the exported launcher.
- **AS-6 — Replace the grep tests.** Use Compose semantics and UI tests instead, add a golden that includes a dialog, and swap the sleeps for state-based awaits.
