# ADR-0019: Minimum Android version 8.0 (API 26)

Date: 2026-11-27
Status: accepted by the owner on 2026-11-27 for P1-21. Device verification on
API 26 is pending (a gap; see `docs/verification/P1-21-min-sdk-26.md`).

## Context

`openlife-design-v0.3.md` proposed minSdk 29 (Android 10), and ADR-0001 item 2
kept it because nothing in the build environment forced a change. The owner's
only physical test device is a tablet on Android 8.0 (API 26).
Emulators are not used for this project, so a minimum above 26 would leave the
owner's device outside the tested product.

A trial build with minSdk 26 compiled and merged its manifest. `lintDebug`
reported five errors, all calls or attributes newer than API 26:
`GET_SIGNING_CERTIFICATES` and `PackageInfo.signingInfo` /
`SigningInfo.getApkContentsSigners` (API 28) in `AppAboutPort`, and
`android:windowLightNavigationBar` (API 27) in both theme files.

## Decision

- `minSdk = 26` for `app` and `vault`. `compileSdk` and `targetSdk` stay 37.
- **Signing certificate (About).** API 28+ reads `signingInfo.apkContentsSigners`.
  API 26-27 read the legacy `PackageInfo.signatures`, which holds the
  certificates that signed the APK. Those versions have no rotation history,
  so the sets are the same.
- **App lock authenticator (ADR-0004).** API 30+ uses
  `BIOMETRIC_STRONG | DEVICE_CREDENTIAL`. API 26-29 use
  `BIOMETRIC_WEAK | DEVICE_CREDENTIAL`, because the framework does not accept
  STRONG with the credential below 30. The choice is `allowedAuthenticatorsFor`.
- **USE_FINGERPRINT.** `androidx.biometric` 1.1.0 declares the legacy
  `USE_FINGERPRINT` permission with no maximum SDK, and it is needed below
  API 28. The app manifest declares it with `android:maxSdkVersion="27"`, so
  the merged release manifest carries it only for API 26-27.
- **Light navigation-bar icons.** `windowLightNavigationBar` is declared only in
  `values-v27` and `values-night-v27`. On API 26 the light icons come from the
  activity's `enableEdgeToEdge()` call: the activity library's `EdgeToEdgeApi26`
  calls `WindowInsetsControllerCompat.setAppearanceLightNavigationBars`, which
  sets the `SYSTEM_UI_FLAG_LIGHT_NAVIGATION_BAR` flag from API 26. This was
  checked by reading the bytecode of the cached AndroidX AARs (activity 1.13.0,
  core 1.19.1); it is not a device observation.
- **Keystore wrapping key (`KeystoreWrapper`).** The `KeyGenParameterSpec`
  options set are: purposes ENCRYPT | DECRYPT, block mode GCM, padding NONE,
  key size 256, and `setRandomizedEncryptionRequired(true)`. All of them are
  API 23+. `setIsStrongBoxBacked` (API 28+) and `setUnlockedDeviceRequired`
  (API 28+) are not set, so no StrongBox request is made below API 28.
  `KeyInfo.getSecurityLevel()` is read only on API 31+; below that, only
  `isInsideSecureHardware` is reported, as in the code before this change.

## Consequences

- `USE_FINGERPRINT` is in the merged release manifest for API 26-27 only.
  `INTERNET` remains absent. `ManifestBoundaryTest` pins both.
- On API 26-29 the app lock accepts a weak-class biometric or the device
  credential. A weak biometric can open the lock where API 30+ requires a
  strong one. The lock stays an access gate (ADR-0004): Keystore keys are still
  not bound to authentication, so the vault's cryptographic protection does not
  change with this decision.
- There is no StrongBox below API 28. On API 26-27 the wrapping key is reported
  only as "inside secure hardware or not" (or software), which is what About
  shows.
- The test matrix grows. CI still runs API 29 and API 36 legs only; no API 26
  CI leg was added, and emulators are excluded by the owner. API 26 evidence can
  come only from the physical tablet.
- Instrumented coverage narrows on API 26-28 in two places. The device-credential
  test (A-12) now covers API 26-29 and skips elsewhere. `SecureWindowUiTest`
  skips below API 29 because `WindowInspector` is API 29+, so FLAG_SECURE on
  API 26-28 has no automated check.
- The PDF row of the design (`PdfRenderer` over memfd, API 30+) becomes "refuse
  below API 30" under this minimum. That is the one design statement that must
  be re-read when the PDF step is specified.

## Not verified

- Every behaviour on a device. Lint and JVM tests pass locally, and nothing has
  run on the API 26 tablet. The checklist is in
  `docs/verification/P1-21-min-sdk-26.md`, and each item is a gap until the
  owner records a run there.
- The light navigation-bar appearance on API 26 (the bytecode reading above is
  not a device check).
- Photo Picker behaviour below API 33: `PickVisualMedia` falls back to a
  document or content picker where the system picker is absent.

## Revisit when

- The owner adds a CI leg for API 26, or a second device, or the minimum
  changes again.
- The PDF step (P7-02) is specified.
