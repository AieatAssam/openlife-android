## Stage 0 emulator install/launch check

`./gradlew :app:installDebug` succeeded on `dev36` (API 36); `adb shell am
start -n org.openlife/org.openlife.app.MainActivity` launched it, and
`dumpsys activity activities` confirmed `topResumedActivity` stayed
`org.openlife/.app.MainActivity` throughout. `adb logcat` showed no
`FATAL EXCEPTION` or crash referencing `org.openlife` at any point.

Note for future stages: this emulator instance was, independently of
OpenLife, under heavy host CPU contention during this session — cold boot
took over 30 minutes with the AVD's existing snapshot and repeated
`system_server` watchdog restarts, then ~50 seconds after `-wipe-data`
discarded the stale snapshot. After launching OpenLife, the *system*
Pixel Launcher and System UI (not OpenLife) intermittently showed "isn't
responding" dialogs from the same host contention, which is why a clean
screenshot of the placeholder screen wasn't captured this session. This is
recorded as an environment characteristic to expect in later stages, not a
defect in the app under test.

## Known environment limitations (carried into the handoff)

- No physical Android device available; all instrumented evidence comes from
  the `dev36` emulator (API 36, Pixel 7 profile, x86_64).
- No API 29 (declared `minSdk`) system image installable — the Android SDK in
  this environment is a read-only Nix store path.
- Device-transfer and manufacturer-specific backup behaviour (R2) cannot be
  fully exercised on an emulator.
