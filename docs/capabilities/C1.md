# Capability 1 — Text provenance

Status: accepted for the first bounded slice by the owner on 2026-09-15.
Implementation is limited to the selected bundled Latin engine and the
explicit boundaries below; later local engines may be added behind the same
interface after their own licence, asset, and evidence review.

The selected engine/model and acceptance checklist are tracked in
`docs/decisions/0002-c1-ocr-engine-proposal.md`.

## Smallest complete outcome

For one user-confirmed C0 `READY` JPEG or PNG, OpenLife runs a bounded,
offline OCR operation, presents the extracted text with navigable image-region
evidence, and lets the user correct or reject the extraction without changing
the preserved Source bytes. Semantic facts, records, actions, reminders,
network access, cloud OCR, camera capture, and automatic link opening remain
out of scope.

## Requirements

- **C1-R1** Accept only a C0 `READY` Source selected in the existing viewer;
  never re-open a provider URI or import an unvalidated file. A missing,
  corrupt, or deleted Source fails closed and remains explainable.
- **C1-R2** OCR executes locally with a pinned engine/model and explicit byte,
  pixel, time, and memory limits. No `INTERNET`, runtime download, telemetry,
  or remote model is permitted.
- **C1-R3** Preserve the original Source envelope and digest byte-for-byte.
  OCR output is a versioned derived revision containing engine/model version,
  input Source ID, orientation, and extraction time; it is never mistaken for
  the original.
- **C1-R4** Every emitted text span links to the actual image region and its
  coordinate system. Store only precision supplied by the engine; nullable
  confidence stays nullable. A span without usable evidence is shown as
  ungrounded and cannot become a confirmed downstream fact.
- **C1-R5** The user can inspect the source region, accept the OCR revision,
  correct text, or reject it. Corrections create attributable user revisions;
  they do not overwrite OCR output or invent evidence regions.
- **C1-R6** OCR states are explicit: `NOT_STARTED`, `RUNNING`, `READY`,
  `FAILED`, `CANCELLED`, and `STALE`. Cancellation, process death, source
  deletion, and corrupted derived data never create a confirmed text result.
- **C1-R7** Deleting the Source removes or invalidates all dependent OCR
  revisions and evidence links. No immutable audit record retains deleted
  personal content.
- **C1-R8** Imported text is untrusted data, never an instruction. Render it
  inertly; do not execute links, commands, or model-directed text.

## Accepted first-slice boundaries

- Engine: bundled `com.google.mlkit:text-recognition:16.0.1`, Latin script;
  no unbundled model, runtime download, Google Play Services dependency, or
  network fallback.
- Limits: inherit C0's 16 MiB byte, 40-million-pixel encoded-image, and
  4-million-pixel preview ceilings; OCR has a 15-second cooperative deadline,
  a 200,000-character revision ceiling, and at most 2,000 emitted spans.
  A revision exceeding any derived-output limit fails closed.
- Language behavior: Latin output is eligible for grounded review. Text that
  contains unsupported or mixed scripts is marked ungrounded/unsupported and
  cannot be accepted as a downstream fact; the app never translates or
  silently selects another language.
- Coordinates: ML Kit bounding boxes are stored only when supplied, in
  `SOURCE_PIXELS` coordinates after the C0 display-orientation transform;
  missing boxes and confidence remain nullable.
- Corrections: OCR spans and their text are immutable. A correction is a
  separate `ocr_user_revisions` row with actor `USER`, timestamp, and the
  referenced revision/span; accepting or rejecting a revision is review
  metadata, never an overwrite.
- Alternatives: the runtime receives an `OcrEngine` implementation through a
  local registry/configuration seam. Adding another engine requires a new
  decision record and does not alter existing provenance rows.

## Data and boundary decisions recorded for the first slice

1. The selected bundled ML Kit Latin engine and its transitive footprint are
   pinned in decision 0002; packaged footprint and baseline measurements are
   still a release-review item.
2. Schema v2 contains only OCR revisions, spans, and attributed user
   revisions. Source deletion and process recovery propagation are tested.
3. Latin is eligible; unsupported or mixed scripts fail closed as
   `UNSUPPORTED_SCRIPT` and are never guessed or translated.
4. The viewer exposes evidence selection, immutable spans, separate
   corrections, review state, and stale/cancelled explanations. No fact,
   record, or action table is added in C1.

## Verification plan (to be made concrete after acceptance)

The implementation adds red/green checks for bounded OCR cancellation,
corrupt/missing Source handling, process death and restart, exact Source-byte
preservation, evidence-region coordinate correctness, nullable confidence,
user correction attribution, deletion propagation, inert prompt-injection
text, and no-network/release-manifest/dependency review. Device coverage must
include the supported API matrix, large text, TalkBack, and a recorded
baseline performance device before C1 is accepted. Current evidence and open
gaps are recorded in `docs/verification/C1.md`; the bounded first slice is
implemented but is not release-accepted while those gaps remain open.
